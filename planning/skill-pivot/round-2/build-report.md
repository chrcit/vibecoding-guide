It also blocked a variant that swapped the removal for an `echo`, because `rm` was still in the substitution pattern. I didn't work around the check. Unverified: the subshell plus EXIT-trap cleanup, and the clone → install path through the one-liner. `install.sh` itself is fully tested (below).
- **Neon §4 extras not in the plan:** copying from an allowlist instead of `cp -R`, warning on `--global --link` from an installed copy, and warning when `--dir` is combined with `--global`. Left out per "add nothing beyond the plan".
- **Welcome-page "Start" button, which installer to pick, and where the new-thread button is on `/start/`** (Neon §5 gaps that are not in item 11). Left out for the same reason.
- **Picker check** (does `$` list the skill right after install in the web UI?). Per "After advice", that is round 2's review job. The page and skill still give both recoveries from the docs: **Restart agent session**, or a new thread.
- **Pinning to a release tag.** That's a launch note for the owner. `skill.branch` is still `main`, so the button and the terminal lines fail until the skill is merged to `main`.
