# Round 2 advice

- **1 · Supervised.** The tagged docs say: “In a thread on your default mode, open the model picker and choose Permissions at its bottom, or press `mod+shift+a`.” A new thread shows its mode under the composer. An existing thread on a different mode shows it beside the model. Have learners check the mode again when moving to a fresh thread. [T3 Code v0.1.9 permission modes](https://github.com/pingdotgg/t3code/blob/v0.1.9/docs/user/permission-modes.md)
- **10 · Drop the automatic commit.** It contradicts the skill’s rule against unasked commits and can stall on an empty folder, missing Git identity, or an approval prompt. Offer a snapshot after the first result, with explicit consent and a list of files it covers. Drop “anything after this snapshot can be undone.” Git can restore tracked files to the snapshot. New untracked files require separate handling.
- **4–6 · Keep the pacing flexible.** Use reply numbers as test checkpoints. Let “put Sedge first” get the revised result immediately. Keep any extra step reversible and tied to the ask. Ask about explanation style once if needed. Confirm any inferred level before including it in the exact text offered for saving.
- **3 · Make the handoff a real test.** Open a plain thread in the same project with a small invented task and no hint of the saved rule. Check whether reply one follows it. The scientist’s thread quoted the rule later and gave three actions upfront. Give the skill invocation separately. A global skill install makes the guide available in another project. The saved project preference stays behind.
- **9/11 · Add picker recovery.** Test the picker after installation. The lab exercised CLI invocation. Verify whether the composer needs a fresh thread or app restart, then document the recovery that actually works.
