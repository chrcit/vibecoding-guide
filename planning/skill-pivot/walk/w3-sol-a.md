## Curriculum review

**L4.** The SQL work made the loop concrete. I could see an unstated definition become a WHERE clause, supply a boundary row that would expose it, and ask the same agent to fix the report. The layers picture worked after the correction because I already knew which parts I wanted to challenge. I would keep the figure there and shorten its long prompt quotation on phones unless the learner asks for it in full. Provenance needs to come with the first result or be evident in what ran. The late disclosure about chart arithmetic and the extra claimed file reads weakened the lesson in checking. As this analyst, I'd borrow “Show me the output that proves it works” and “Run it on five different inputs, including one that should break it.” I'd name the actual boundary rows in the second sentence.

**L6.** Editing the card in one sentence made the page move tangible. So did seeing the guide return local retry checks while the audit was still running. The other thread's replay example made the reference move worth using. I'd keep this sequence and attach the harness-specific context explanation to the first fresh-thread offer. A later correction leaves room for the learner to start independent work with a mistaken assumption about what the new thread sees. The four mechanism reads, layers template, and multiple previews before the first card added delay before the learner had anything to react to. The mobile height problem only appeared when the enlarged German page was opened, so the narrow-width check belongs on the longest state. As this data engineer, I'd reuse “Bigger, and in German,” “Start a thread that does X while this one keeps going,” and “@thread-name: what did it find? Compare it with what we have here.” For a handoff decision, I'd add “Show what it ran and observed, and what it only proposed.”
