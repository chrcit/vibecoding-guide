## What's genuinely new here

Each piece has been done somewhere. I found nothing that combines them:

1. **The agentic workflow is the subject.** Every in-agent tutorial above teaches either tool features (Discord, `/powerup`, Nimbalyst) or code concepts (Learning style, learn-while-build). None teaches context, verification and orchestration as concepts.
2. **Visuals render inline in the thread** (T3 `html_render`) and can open in a side tab. Existing skills write a separate HTML file and open a browser ([visual-explainer](https://cdn.jsdelivr.net/npm/visual-explainer@0.8.1/README.md), [codebase-to-course](https://github.com/zarazhangrui/codebase-to-course)). `/powerup` animates, but only its own canned demos.
3. **Lessons demonstrated by the tool itself**, for example nested `delegate_task` children the learner can watch. I found no course that uses the IDE's own multi-agent features as the demonstration.
4. **One static skill that also stays a readable website**, with no server (LessonFolk needs one) and no single-vendor lock-in.
5. **A knowledge base built from the learner's own sessions**, scoped to agentic practice. learn-while-build does this for code concepts only.

## What has been tried and fell short

- **Prompt guardrails leak.** The CS50 Duck was told not to answer with blocks of code "and yet it still does up to a quarter of the time" ([Harvard Gazette, 2026-09](https://news.harvard.edu/gazette/story/2026/09/taming-the-duck-for-starters/); [paper](https://cs.harvard.edu/malan/publications/fp0627-liu.pdf)). Claude Code's docs give the same warning for output styles and point to hooks for anything that must always happen ([docs](https://code.claude.com/docs/en/output-styles)).
- **Delegating hurts learning; asking helps.** In Anthropic's RCT (52 developers), AI help lowered comprehension, with the biggest gap on debugging. People who asked conceptual follow-up questions did better than people who delegated ([Anthropic, 2026-01-29](https://www.anthropic.com/research/AI-assistance-coding-skills); [arXiv](https://www.arxiv.org/pdf/2601.20245)). A TUM study found unrestricted AI produced a "comfort trap", while a hint-only tutor raised motivation ([TUM](https://www.edtech.tum.de/?p=3520); summary only, unverified). This matters for us because our course teaches delegation.
- **Text-only in-agent tutorials get little attention** (Discord 3 stars, learn-while-build 0, visual codebase-to-course 5.8k). Stars measure attention, not learning (observation).
- **Little evidence for learner-chosen projects.** I found no outcome study. The nearest, [AutoPBL](https://pi.cs.tsinghua.edu.cn/wp-content/uploads/2025/06/AutoPBL.pdf) (self-directed, LLM-guided projects), reports gains. Open-ended work also loses the known solution that Epic or rustlings check against.
- **Codex has no learning mode**, only a [feature request](https://community.openai.com/t/add-a-teach-me-before-editing-mode-to-codex/1399896.md) and community skills, so the skill has to carry its own teaching behaviour.

## Five lessons to steal

1. **Keep a progress file in the learner's repo**, like the Discord tutorial's `.claude/tutorial-progress.md`. Lessons resume across threads, and the file seeds the knowledge base.
2. **Use a deliberate handoff, one at a time.** Learning style puts one `TODO(human)` at a real decision point, then stops and waits. For us, the learner's part should be the decision or the verification, such as reading the diff, running the check or picking among the agents' outputs, not typing code.
3. **The learner approves what goes in the knowledge base.** learn-while-build drafts concepts at the end of a session, each tied to the file where it came up, and saves only what the learner approves. Scheduled review brings them back.
4. **Prompt for questions, not just delegation.** Following the Anthropic RCT, each lesson should end by having the learner ask or answer a "why" about what the agent did, not only send the next task.
5. **Make checks structural, not instructions.** Prompts leak (CS50, the output-style docs). Each lesson needs something observable the learner can verify, the way Epic has a Diff tab and rustlings has a passing build. Every visual should also work as a standalone HTML file, so it still works outside T3 Code, as codebase-to-course and visual-explainer do. That matches tstack's approach of using T3 features when present and falling back otherwise.
